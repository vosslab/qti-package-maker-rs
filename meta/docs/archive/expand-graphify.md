# Prune Rust test symbols, then publish a GitHub-visible map page

## Context

The previous session widened `devel/graphify_map_repo.py` to use Graphify properly: it split
`devel/graphify_context_lib.py` out, filtered connector and relationship noise, surfaced
architectural hubs, and added lifecycle flags. That work is done and green (2259 tests).

Two things came out of it that this plan finishes.

**1. The Rust test-symbol filter is presentational, and it should not be.** Graphify's Rust
extractor indexes `#[cfg(test)] mod tests` contents as production symbols, because `walk()` in
`graphify/extractors/rust.py` reaches `mod_item` through its generic fallback (line 334) and
never inspects an `attribute_item`. Those modules live inside `src/*.rs`, so `.graphifyignore`
cannot exclude them without dropping the production code beside them. The current filter hides
them at print time while they remain in `graph.json`, still skewing community detection, hub
degree ranking, and connector spread.

`graphify cluster-only <path>` re-clusters an existing `graph.json` and regenerates the report.
That makes a real fix possible locally: prune the test nodes from `graph.json` between
extraction and clustering, so clustering never sees them. This is the "fix the design, not the
symptom" version, and it also improves the diagram in part 2, since communities are what the
diagram draws.

**2. A GitHub-visible map page.** Graphify can produce something worth showing, but only one
route renders natively on GitHub, and two obvious routes are traps:

- `export callflow-html` embeds 13 Mermaid diagrams, and GitHub renders ```mermaid fences
  natively. But Graphify hardcodes `%%{init: {"theme": "dark", ...}}%%` with `htmlLabels` and
  `<small>` tags, which renders wrong in GitHub light mode and risks sanitization. Its
  per-section diagrams are also 63-node `package.json` dependency dumps.
- `export svg` renders on GitHub but is 1.9 MB. Measured cause: it is matplotlib output whose
  text is emitted as 17,933 per-glyph `<use>` references, not metadata bloat. It is also
  illegible: 452 filename labels overlap into spaghetti.
- `export html` and `tree` need JavaScript and cannot run on GitHub at all.

The SVG is salvageable, and precisely so. Its groups are matplotlib-structured (`figure_1`,
`axes_1`, `legend_1`, `line2d_N`, `text_N`), and the counts line up exactly: 478 `text_N` groups
= 452 node labels + 26 community labels, where the 26 live inside `legend_1`. So "drop every
`text_*` not descended from `legend_1`" removes the filename spaghetti and keeps the labels that
name the clusters - no heuristics and no filename matching. Measured on this repository:

| Variant | Size |
| --- | --- |
| Raw SVG | 1934 KB |
| Raw PNG | 256 KB |
| Cleaned SVG | 518 KB |
| Cleaned PNG | 99 KB |

The committed asset is the **cleaned SVG**: vector, so the legend stays crisp and a reader can
zoom into dense cluster regions.

So the page generates its own Mermaid from `graph.json` rather than scraping Graphify's HTML.
That avoids depending on upstream markup that changes often, reuses loaders that already exist,
and lets us control theme neutrality and label sanitization. Measured: the 1.9 MB SVG converts
to a **256 KB** PNG at 1600px with a 64-colour palette, which is reasonable to commit.

Out of scope by explicit instruction: **no git hooks, no GitHub Actions, no CI.** The page is
generated by a manual command, the same way the map is.

## Part 1 - Prune Rust `#[cfg(test)]` symbols before clustering

### 1a. New module `devel/graphify_prune_tests.py`

Graph surgery is a separate concern from orientation, and both existing modules are partway to
the 1000-line ceiling (`graphify_map_repo.py` 562, `graphify_context_lib.py` 694), so this is a
third flat sibling helper - the pattern `devel/DEVEL_README.md` already blesses.

Find `cfg(test)` spans precisely with tree-sitter rather than by regex or brace counting:

- Collect distinct `source_file` values ending in `.rs` from the graph's nodes.
- Parse each file with `tree_sitter` + `tree_sitter_rust`.
- Record the line span of every `mod_item` whose preceding sibling is an `attribute_item`
  containing `cfg(test)`, and every `function_item` attributed `#[test]` (covers
  `#[tokio::test]` too).
- Drop a node when its `source_file` matches and the line parsed from its `source_location`
  (`"L123"`) falls inside a recorded span.
- Drop every link whose source or target was dropped.
- Keep nodes with an empty `source_file`: those are the deliberate sourceless cross-file stubs
  the extractor emits for corpus-level rewiring.

`tree-sitter` and `tree-sitter-rust` already install as Graphify dependencies, but this repo
imports them directly, so both are declared in `pip_requirements-dev.txt`;
`tests/test_import_requirements.py` enforces that. Their import names need no alias entry.

### 1b. Rework the fresh pipeline, gated on repository evidence

Only change the pipeline when pruning actually applies, so non-Rust consumers keep today's exact
behavior. The gate is `Cargo.toml` at the repo root - the same evidence that already selects
`--cargo` in `graph_build_command`.

When it applies, the fresh path becomes extract, prune, then cluster:

1. `graphify extract . --code-only --cargo --no-cluster`
2. prune `graph.json`
3. `graphify cluster-only .` (with `--no-label`, the existing label step still follows)

`--no-cluster` avoids clustering twice, since clustering on the unpruned graph would be thrown
away. Everything downstream - labeling, benchmark, edge-fidelity diagnostics, orientation - is
unchanged and now runs against a graph with no test symbols in it.

Pruning is automatic rather than flag-gated. It is a correctness fix, and argparse minimalism
says not to add a flag for something no one should routinely turn off. Print how many nodes and
edges were removed so the change is never silent.

### 1c. Keep the presentational filter

Do not remove `is_test_symbol` from `devel/graphify_context_lib.py`. It still covers repos this
pruning does not reach: other languages' inline test conventions, and Rust repos whose graph was
built before this change.

## Part 2 - `docs/GRAPHIFY.md`, generated per repository

### 2a. Propagation: the page must never ship

This is the same trap that ruled out `docs/USAGE.md` last session. Files under `docs/` propagate
by overwrite, so a template-owned `docs/GRAPHIFY.md` would replace every consumer's page -
describing the wrong repository - on the next sync.

Add **exact** entries to `meta_files` in `meta/propagation/manifests.yaml`:

- `docs/GRAPHIFY.md`
- `docs/GRAPHIFY_map.svg`

Exact entries, not a `meta_file_patterns` glob: `classify_bucket` in
`tests/meta/test_link_bucket_isolation.py` consults `META_FILES` and `META_DIRS` but not the
pattern list, so only an exact entry classifies the page as `meta` and lets it link anywhere
(`meta -> any bucket` is allowed). A glob would leave it classified `universal`, which forbids
linking to `meta` paths.

This is the sanctioned kind of manifest entry - location cannot express the routing fate -
and it is exactly how `docs/CHANGELOG.md` and `docs/TODO.md` are already handled.

The generator ships (it lives in `devel/`); its output does not. The template commits its own
page and image, which is how this repository gets a visual on GitHub.

### 2b. New module `devel/graphify_docs_lib.py`

Page generation is its own concern and keeps `graphify_context_lib.py` under budget. It reuses
that module's existing loaders (`load_graph_data`, `load_analysis_data`, `load_labels_data`,
`clean_graph_text`, `is_test_symbol`) rather than re-reading artifacts.

**Community overview diagram.** Nodes already carry `community` and `community_name`, so the
diagram needs only `graph.json`:

- Group nodes by community; count each.
- For each link, map both endpoints to communities; count cross-community pairs as edge weight.
- Emit `flowchart LR`, one box per community labelled `Name (N)`, edges between them.
- Cap to the largest communities (about 12) so the diagram stays readable.

Two rules that come straight from the traps found above:

- **Emit no `%%{init}%%` directive.** GitHub themes Mermaid for the reader; Graphify's hardcoded
  dark theme is wrong in light mode.
- **Plain-text labels only.** No `<br/>`, no `<small>`, no HTML entities - GitHub sanitizes
  Mermaid HTML labels. Sanitize node ids to `[A-Za-z0-9_]` and keep labels ASCII, which
  `tests/test_ascii_compliance.py` requires anyway.

**Stats and map summary.** Node and edge counts, community count, a file-type mix derived from
`source_file` extensions, and a community table (name, node count). The benchmark
token-reduction figure comes from `graphify benchmark`, whose output is parsed for the
`Reduction:` line - treated as advisory, so a parse failure omits the figure instead of failing
the page.

**Per-community detail sections.** One section per community with its highest-degree symbols,
degree computed from the links already loaded. Tables, not generated per-section diagrams:
Graphify's own per-section diagrams are the 63-node dependency dumps described above, and the
same "cap the spread" lesson from the connector filter applies.

**Full-graph image.** Run `graphify export svg`, pass it through the cleaner in Part 3, and
write `docs/GRAPHIFY_map.svg`. No raster step and no ImageMagick dependency in the shipped path.

This image is **decorative**. It shows cluster shape and scale; the Mermaid overview is what
explains the architecture, and the tables are what carry the detail. Treat the whole image step
as non-fatal: if `graphify export svg` fails or the cleaner cannot parse its output, warn and
write the page without the figure rather than failing the run. Nothing downstream depends on it.

### 2c. New `--page` mode

Add `MODE_PAGE` to the existing mutually exclusive mode group in `build_parser`, beside
`--context` and `--reflect`. It reads existing artifacts and writes the page without rebuilding
the map, matching how `--context` already behaves. When no map exists it prints the same
guidance `--context` does rather than erroring.

## Part 3 - SVG cleaner, `devel/graphify_clean_svg.py`

Prior art exists at
`~/nsh/TYPESCRIPT/virtual-lab-protocol-simulation/tools/svg_normalizer/`, but it is a
6,400-line `lxml` package for hand-authored lab illustrations - clip geometry, shadows,
transform trees, identity sweeps. Wrong shape for a machine-generated matplotlib graph, and
vendoring it into a template that ships to every repository would be a large dependency for a
narrow job. Reuse the idiom and the dependency (`lxml.etree`, already on this machine and
declared in `pip_requirements-dev.txt`), not the package.

Three passes, in order, each measured so a regression is attributable:

**Pass 1 - drop node labels.** Collect the ids of `text_*` groups inside `legend_1`, then remove
every `text_*` group not in that set. Skip comment and processing-instruction nodes: `lxml`
yields them from `iter()` and their `.get()` returns `None` regardless of the default, which is
a real crash and not a hypothetical (it was hit while measuring this). Measured 1934 -> 518 KB.

**Pass 2 - garbage-collect dead glyph defs.** After pass 1 most font glyph paths are
unreferenced. Reference-count *after* pass 1, scanning both `xlink:href="#id"` / `href="#id"`
on `<use>` and `url(#id)` inside any attribute value (`clip-path` uses this form). Remove only
`<defs>` children whose id has a zero count. Counting both reference forms is what protects the
26 legend labels and the clip paths from being collected.

**Pass 3 - round coordinates.** Matplotlib emits roughly six decimals. Rewrite numeric tokens in
`d`, `transform`, `x`, `y`, `width`, and `height` to a fixed precision held as a module
constant, not a CLI flag. Touch numeric tokens only, never path command letters.

The image is decorative - it conveys cluster shape and scale, not readable detail - so this pass
can round hard. A sub-pixel shift in a picture nobody measures costs nothing, which is why it
gets an eyeball check rather than a pixel-diff harness.

## Verification

1. **Pruning is correct on real Rust.** This template is Python and has no `Cargo.toml`, so
   pruning cannot be exercised here end to end. Unit-test span detection against small Rust
   fixture strings written to `tmp_path` (a `#[cfg(test)] mod tests` block, a `#[test]` fn, and
   a production fn that must survive). Then run the real pipeline once against the Rust repo
   that produced the earlier sample and confirm
   `denied_active_membership_policy_and_feedback_never_produces_preview_data()` and the other
   two are gone from both the orientation **and** `graph.json`. **This step needs the user to
   name that repository.**

2. **Non-Rust repos are untouched.** Assert `graph_build_command` produces today's exact
   argv when no `Cargo.toml` is present, so the pipeline change cannot regress every other
   consumer.

3. **Mermaid is theme-neutral and sanitization-safe.** Assert the generated block contains no
   `%%{init`, no `<br/`, and no `<small`, and that node ids match `[A-Za-z0-9_]+`.

4. **The SVG cleaner keeps what it must and changes nothing visible.** Unit-test each pass
   against a small inline SVG fixture: a `text_` group inside `legend_1` survives while one
   outside it is removed; a `<defs>` entry still referenced by `url(#id)` survives while an
   unreferenced one is collected; rounding rewrites numbers without touching path command
   letters; and a comment node in the tree does not crash the walk.

   The image is decorative, so pass 3 needs no pixel-comparison harness: open the cleaned SVG
   in a browser once and confirm the cluster shape still reads and the legend is intact. If
   rounding ever visibly distorts it, lower the precision constant.

5. **Propagation routing.** `source source_me.sh && pytest tests/meta/ -q` - the page must
   classify as `meta`, must not appear in any propagation plan, and
   `tests/meta/test_link_bucket_isolation.py` plus
   `tests/meta/test_no_meta_content_leaks.py` must stay green. The previous session hit both of
   these with a meta-path link, so they are the ones to watch.

6. **Full suite and lint.** `source source_me.sh && pytest tests/` including
   `test_markdown_links.py` (the page links to the committed SVG, which must exist),
   `test_ascii_compliance.py`, `test_import_requirements.py` (new `tree-sitter`,
   `tree-sitter-rust`, and `lxml` declarations), and `test_source_file_line_limit.py`.

7. **Real page generation.** `source source_me.sh && python3 devel/graphify_map_repo.py --page`,
   then confirm `docs/GRAPHIFY_map.svg` lands near 518 KB or below, opens correctly in a
   browser, and shows the legend with no filename labels. GitHub's Mermaid and SVG rendering
   cannot be verified locally - check the pushed page in both light and dark theme.
